Thinking with Reasoning Skills: teaching models when to use extended chains of thought

Researchers from the ACL 2026 industry track present a method for training language models to selectively engage extended chain-of-thought reasoning only for problems that genuinely require it. The result: fewer tokens on easy tasks, no accuracy regression on hard tasks, and a practical training recipe that can be applied to any instruction-tuned base model. The paper lands at exactly the moment practitioners are asking whether reasoning models' verbosity is a cost problem or a quality problem. The answer, per this work, is both — and you can fix the cost without sacrificing the quality.

03 THE PAPER
METHODOLOGY · FINDINGS
THE PROBLEM

Reasoning-capable models — those trained with extended chain-of-thought — apply long scratchpads indiscriminately. Ask one what 2 + 2 equals and it may spend 400 tokens working through an arithmetic proof. This verbosity has a real cost: inference latency, API billing, and context window consumption. Prior work addressed this by shortening chains globally. That approach degraded accuracy on hard problems. This paper reframes the objective: the model should select the appropriate reasoning depth per problem, not per temperature or instruction.

THE APPROACH: REASONING SKILL CLASSIFICATION

The authors define a taxonomy of reasoning skills — direct recall, single-step inference, multi-step deduction, mathematical reasoning, code synthesis, and creative generation — and label a training dataset by the minimal skill required per problem. Phase 1 of training teaches the model to classify incoming prompts against this taxonomy before generating a response. Phase 2 fine-tunes the model on skill-stratified completions: short direct answers for recall problems, full scratchpads for multi-step and mathematical ones. The result is a model that routes internally, with no external classifier and no special tokens.

KEY FINDING: DIFFICULTY AWARENESS IS LEARNABLE

The most significant finding is not the token reduction — it is that difficulty awareness generalises. Models trained on the stratified dataset correctly classify out-of-distribution problem types they were not explicitly trained on. The authors attribute this to the internal representations learned in Phase 1: the classification head learns a latent difficulty manifold that transfers across domains. This suggests the approach can be applied to specialised domains (legal reasoning, biomedical Q&A, code debugging) without needing a domain-specific difficulty taxonomy.

WHY IT MATTERS NOW
Reasoning model API costs are typically 3–8× higher than standard models. A 38% token reduction on a mixed workload translates directly to a ~20% bill reduction with no prompt changes required.

05 WHAT IT MEANS
SIGNAL / NOISE
A
REASONING IS NOT BINARY
The field has been debating "should I use a reasoning model or a standard model?" This paper dissolves the question. A model that knows when to reason is strictly better than either — it matches the accuracy of a full reasoning model at the cost profile of a standard one on easy tasks.
B
FINE-TUNING IS THE LEVER, NOT PROMPTING
System-prompt hacks like "be concise" suppress verbosity without targeting it. This approach trains the right internal behaviour. The token savings are consistent across request types; prompt-based suppression is not.
C
EVALUATION BENCHMARKS NEED A DIFFICULTY AXIS
The paper's taxonomy exposes a gap in standard eval sets: most benchmarks report accuracy but not tokens-per-correct-answer stratified by problem difficulty. That metric would make models' reasoning efficiency visible in leaderboard comparisons.

06 IMPLEMENTATION OVERVIEW
PAPER.1 · PRACTITIONER GUIDE
PHASE 1 — SKILL CLASSIFIER TRAINING

Start with any instruction-tuned base model. Construct a labelled dataset of ~50K prompt-skill pairs using the six-category taxonomy. Instruction-tune a lightweight classification head (a linear layer over the final hidden state) for 2 epochs at 1e-4 learning rate. The head adds <1% to inference latency and no tokens to output. Validate against a held-out set; target >90% classification accuracy before proceeding to Phase 2.

PHASE 2 — STRATIFIED FINE-TUNING

Construct a second dataset of ~200K prompt-completion pairs, stratified by difficulty: 40% direct-answer problems with short completions, 30% single-step inference, 30% multi-step or mathematical problems with full chain-of-thought completions. Fine-tune the full model for 3 epochs. The stratification ratio matters: skewing toward easy problems causes accuracy regression on hard tasks; skewing toward hard problems reduces token savings on easy tasks. 40/30/30 is the paper's recommended starting point.

EVALUATION

Evaluate against a mixed benchmark that includes both easy (trivia, direct factual) and hard (MATH level 4-5, LiveCodeBench, multi-hop reasoning) problems. Track two metrics in parallel: accuracy delta vs. baseline, and mean tokens-per-correct-answer stratified by difficulty tier. A successful run should show <1% accuracy delta on hard problems and >30% token reduction on easy problems. If accuracy drops on hard problems, revisit the Phase 2 stratification ratio; if token reduction is low, revisit Phase 1 classification accuracy.

QUICK-START CHECKLIST
1.
Label 50K prompts against the six-category taxonomy — use GPT-4 class or equivalent for annotation speed.
2.
Train classification head to >90% accuracy. Freeze base model weights in Phase 1.
3.

4.
Fine-tune full model. Monitor loss curves for both difficulty tiers separately.
5.
Evaluate on mixed benchmark. Target <1% accuracy delta, >30% token reduction on easy tasks.
COMPUTE REQUIREMENTS
Phase 1 is cheap: classification head training on a 7B model takes ~4 A100-hours. Phase 2 is standard fine-tuning cost. No reinforcement learning infrastructure required. The authors report full replication on a single 8×A100 node for models up to 13B parameters.
