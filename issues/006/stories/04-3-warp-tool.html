Warp Terminal — now open source

AGPL client on GitHub. Kimi K2.6, Qwen3, MiniMax via "auto (open)" routing.

The AI-first terminal used by close to a million developers released its client source on April 28. You can now audit it, fork it, and contribute — with AI agents handling implementation via the Oz platform.

OPEN SOURCE · APR 28 2026 · WARP LABS

★ WHAT IT IS

Warp is an AI-integrated terminal emulator built in Rust with a block-based command history, inline AI completions, and a multi-model routing layer. As of April 28, the client is open source under AGPL at github.com/warpdotdev/warp. The cloud backend (Warp Drive, shared workflows) and the Oz agent orchestration platform remain proprietary. The new release adds support for Kimi K2.6, MiniMax, and Qwen3 alongside existing GPT and Claude model options, routable via an "auto (open)" mode that picks the best available open model for a given task. OpenAI is the founding sponsor of the open-source release.

¶ 01 WHY · IT · MATTERS

The AGPL release unlocks Warp for privacy-conscious developers and enterprises that require source auditability — the single biggest barrier to adoption among security teams. The "auto (open)" routing means you can now use K2.6 or Qwen3 for AI completions inside the terminal without routing prompts through OpenAI, which removes a data-residency concern for many teams. The AGPL licence specifically prevents proprietary forks: any organisation that ships a modified Warp must open-source those modifications, protecting the community investment.

¶ 02 HOW · TO · TRY · IT ~15 MIN
01

Download Warp from warp.dev or build from source at github.com/warpdotdev/warp. If building from source, you'll need a Rust toolchain and the README build instructions.

02

Open Settings → AI → Model and switch routing to "auto (open)". This routes your AI completions through K2.6, Qwen3, or MiniMax rather than GPT or Claude. Run a few completions and observe latency and quality differences.

03

Open a complex debugging session — a multi-step build failure with logs — and ask the AI assistant to diagnose it. Evaluate whether the model selected by "auto (open)" produces a root-cause explanation that would let you fix the issue, or whether it hedges around the problem.

¶ 03 WHAT · TO · OBSERVE

Note that the cloud backend — where Warp Drive shared workflows live — is still proprietary and still sends data to Warp's servers. If your concern is data residency, verify which specific features route through cloud versus local model. Check the AGPL terms before deploying Warp in a product your organisation ships: if your internal tooling bundles or distributes Warp, you may be required to open-source those modifications. Review the Oz contributor model if you're considering contributing — it's AI-agent-mediated, not a traditional patch workflow.
