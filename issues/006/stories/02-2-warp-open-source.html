WHAT · IS · OZ

Oz is Warp's proprietary cloud agent orchestration system. Contributors propose features and verify results; AI agents handle the implementation work. Oz is not open source. The model is: open client for community input, proprietary cloud for AI-assisted development at scale.

OPEN SOURCE TERMINAL DEV TOOLS

Warp has open-sourced its terminal client under AGPL, with OpenAI signing on as the founding sponsor and the company's own agent platform, Oz, powering community contributions through AI-assisted code review and implementation.

¶ 01 WHAT · HAPPENED

Warp Labs published the Warp terminal client to GitHub on 28 April 2026 under an AGPL license. The release covers the client application only — the cloud backend, Warp Drive (shared workflows), and Oz (the agent orchestration system) remain proprietary. The announcement introduced support for three additional open-weight models: Kimi K2.6, MiniMax, and Qwen, plus an "auto (open)" routing mode that selects the best available open model for a given task. OpenAI signed on as the founding sponsor, providing GPT models that power the Oz contributor workflow — meaning contributors submit ideas and verify agent-generated code rather than writing the implementation themselves.

AGPL Any software that distributes a modified Warp must also release its source — ensuring changes flow back to the community
¶ 02 WHY · IT · MATTERS

Terminal tooling has historically been dominated by open-source projects (iTerm2, tmux, Fish). Warp entered as a VC-backed proprietary product competing on AI integration. Opening the client addresses the adoption barrier among privacy-conscious developers and enterprises that require auditability. The OpenAI sponsorship is structurally significant: a major AI lab is directly funding an open-source developer tool to accelerate its own model adoption — a new kind of ecosystem investment. The AGPL licence rather than MIT or Apache means commercial entities that ship Warp forks must open-source their changes, which limits one common route of proprietary capture.

"Opening development with agent assistance enables faster shipping by offloading coding to agents while humans focus on product direction and verification."

— WARP BLOG ANNOUNCEMENT

¶ 03 WHAT · TO · WATCH

Evaluate the AGPL terms before deploying Warp in an enterprise context — if your team ships internal tooling that incorporates Warp, AGPL may require disclosure of those modifications. Try the "auto (open)" model routing if you work with Kimi or Qwen: run a benchmark task on your own codebase and compare latency and output quality against the GPT-backed default. Watch Warp's GitHub contribution velocity over the next 30 days to see whether agent-assisted contributions actually close issues faster than a traditional open-source model.
