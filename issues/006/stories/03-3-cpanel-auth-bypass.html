SECURITY WEB HOSTING

cPanel/WHM auth bypass CVE-2026-41940 exploited in the wild via CRLF injection

All supported cPanel and WHM versions are affected. Attackers are using CRLF injection to bypass session validation and gain unauthenticated administrative access to hosting control panels.

VIA · CPANEL SECURITY · 2 MIN READ

★ WHAT HAPPENED

CVE-2026-41940 is a CRLF injection vulnerability in the cPanel and WHM session authentication layer. By injecting carriage-return/line-feed characters into specific HTTP header fields, an unauthenticated attacker can manipulate the session token validation logic and obtain WHM root-level access without valid credentials. cPanel confirmed active exploitation in the wild in their advisory published April 28. The flaw affects every version in the supported release track, and a patch was pushed via the automatic update mechanism on the same day. Servers with auto-updates disabled are still vulnerable.

¶ 01 WHY · IT · MATTERS

cPanel/WHM runs on a substantial share of shared and reseller hosting infrastructure — estimates put it at over 70 million domains globally. A WHM authentication bypass gives an attacker root equivalent access: they can read all hosted emails, dump databases, plant webshells, and pivot to any site on the server. The attack surface is the WHM port (2087), which many hosts expose directly to the internet. Because cPanel is typically the management layer for many downstream customers, a single compromised server can expose hundreds of independent businesses.

¶ 02 WHAT · TO · WATCH

Confirm your cPanel/WHM version immediately — run cat /usr/local/cpanel/version and compare against cPanel's advisory. If auto-updates are disabled, apply the patch manually before doing anything else. Restrict WHM port 2087 to known management IPs at the firewall level if you haven't already — this is the simplest mitigation for internet-facing panels. Review WHM access logs for the past 72 hours for unauthenticated session creation events. If you're a customer of a shared host, contact your provider to confirm their patch status.
