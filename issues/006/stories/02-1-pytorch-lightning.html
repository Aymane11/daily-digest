SECURITY SUPPLY CHAIN PYTHON

Two malicious versions of lightning — the PyTorch Lightning training library used by thousands of AI projects — were published to PyPI on 30 April 2026 and removed within hours, but not before executing a credential-stealing payload on every machine that ran an import.

¶ 01 WHAT · HAPPENED

TeamPCP — a threat actor linked to LAPSUS$ that previously compromised LiteLLM, Telnyx, and Aqua Security Trivy — hijacked the PyTorch Lightning GitHub account and published versions 2.6.2 and 2.6.3 to PyPI. Each contained a hidden _runtime directory. On import, a Python bootstrap script downloaded the Bun JavaScript runtime, then executed an 11MB obfuscated payload named router_runtime.js. The payload harvested GitHub tokens, SSH keys, AWS and GCP credentials, Kubernetes secrets, and .env files, validated stolen tokens against the GitHub API before use, then injected worm-like commit payloads into up to 50 branches of accessible repositories. Exfiltration routed to zero.masscan[.]cloud:443. The malware also created Claude Code hook files in .claude/ directories to establish persistence on developer machines.

397 HN points — second-highest security story of the week, behind only the OpenClaw incident
¶ 02 WHY · IT · MATTERS

PyTorch Lightning is used across ML pipelines at scale. Any CI environment that ran pip install lightning during the attack window — even as a transitive dependency — executed the payload automatically. The Intercom victim illustrates the transitive risk: their infection came from pyannote-audio, which pulled Lightning as a sub-dependency. The persistence mechanism through Claude Code hooks is particularly novel: it means compromised developer machines remain infected even after the malicious package is removed. The campaign is also escalating: TeamPCP launched a dark web site after X suspended their account, and claims ongoing partnership with LAPSUS$.

"Socket flagged the builds 18 minutes after publication — but the damage window is the entire install period before that alert reached pipeline maintainers."

— EDITORIAL NOTE

¶ 03 WHAT · TO · WATCH

Rotate all credentials immediately if you installed lightning 2.6.2 or 2.6.3 — GitHub tokens, AWS/GCP/Azure keys, SSH keys. Audit .claude/ and .vscode/ directories on any machine that ran pip install during 30 April. Check all accessible git branches for injected commits with unfamiliar author identities. Pin lightning==2.6.1 in lock files until a clean 2.6.4 or later is published and independently verified. Track TeamPCP's next targets — they have publicly claimed more campaigns are planned.
