METHODOLOGY THOUGHTWORKS

Structured-Prompt-Driven Development (SPDD)

How to make AI-assisted changes governable, reviewable, and reusable

BY · WEI ZHANG & JESSIE XIA · 15 MIN READ

★ TL;DR

Thoughtworks developed SPDD to turn AI coding assistance from personal efficiency into an organization-level capability. Treat prompts as first-class delivery artifacts—version controlled, reviewed, and reusable—using the REASONS Canvas to capture requirements, design intent, and constraints before code generation.

¶ 01 WHY · IT · MATTERS

Individual developer speed doesn't translate to team throughput. SPDD addresses the friction that appears at team level: ambiguous requirements become code quickly, reviews have more change to process, and production risk is harder to reason about. The method treats prompts as governed artifacts, enabling AI-First Software Delivery at scale.

¶ 02 THE · REASONS · CANVAS

Seven-part structure for generating prompts: Requirements (what/DoD), Entities (domain), Approach (strategy), Structure (components), Operations (steps), Norms (standards), Safeguards (boundaries). Forces clarity before code generation, moving uncertainty left.

¶ 03 THREE · CORE · SKILLS

1. Abstraction first: design before generate. 2. Alignment: lock intent before code. 3. Iterative review: turn output into a controlled loop. Developers need these skills to be effective with AI assistance.

RECOMMENDED · ACTIONS

1. Try the REASONS Canvas on your next feature. Document requirements, entities, approach, structure, operations, norms, safeguards before prompting.

2. Audit your current prompt usage: Are prompts version-controlled? Reviewed? Reusable?

3. Add three skills to team retros: abstraction-first, alignment, iterative review.

QUICK · START

<30 min: Pick one user story. Apply the REASONS Canvas structure. Generate code. Compare output to ad-hoc prompting.

★ CAREER · APPLICATION

Mental model: Your value is shifting from writing code to directing intent. Experiment: Track one sprint using SPDD vs. ad-hoc prompting—measure review cycles, rework rate, and code quality. Team exercise: Run a prompt review session using the REASONS Canvas as a checklist.
