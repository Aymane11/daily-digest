ProgramBench measures real programming skill — and finds frontier models plateau around 60%

Researchers from Carnegie Mellon and the University of Illinois released ProgramBench, a coding benchmark built to resist dataset contamination by drawing problems from private competitive-programming archives and wrapping them in novel problem statements. Top frontier models — including GPT-4o and Claude 3.5 Sonnet — score around 55–62%, well below human expert levels near 85%.

The core design choice is a two-layer contamination defence: problems come from private judge systems never indexed publicly, and each problem is re-stated with different variable names, narrative framing, and constraints before evaluation. This prevents both memorisation of problem texts and solution-code lookup. The benchmark covers 500 problems spanning algorithms, data structures, and mathematical reasoning — all verified solvable by human experts under timed conditions.

The finding that current frontier models plateau in the high-50s to low-60s percentage range while humans reach 85% is significant because most publicly cited coding benchmarks (HumanEval, MBPP) now see near-saturation scores above 90%. ProgramBench suggests those saturated benchmarks have become proxies for training data coverage rather than generalised programming ability.

What to watch

  • Check the ProgramBench leaderboard when evaluating which model to use for a coding-agent task — a model's HumanEval score and its ProgramBench score may diverge significantly, which is useful signal about generalisation vs. memorisation.
  • Ask your team whether the coding tasks you benchmark internally share characteristics with public datasets; if yes, consider adding a private hold-out problem set using the same contamination-resistance methodology.
