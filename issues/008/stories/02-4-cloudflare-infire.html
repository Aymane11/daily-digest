Cloudflare built a custom Rust inference engine and made Kimi three times faster

Infire, published April 16, replaces vLLM on Workers AI with a Rust-native engine purpose-built for prefill-decode disaggregation, multi-GPU parallelism, and speculative decoding — cutting intertoken latency to 20–30 ms at scale.

¶01 — What happened

Cloudflare's Workers AI team shipped Infire, a Rust-native LLM inference engine they wrote from scratch, after finding that existing open-source options couldn't hit the latency and throughput targets needed to serve frontier models across a globally distributed edge network. The first production workload is Kimi K2.5 from Moonshot AI, and the numbers Cloudflare published show the gap clearly: intertoken latency dropped from roughly 100 ms to 20–30 ms, a 3× improvement.

Infire implements four techniques simultaneously: prefill-decode disaggregation (separate compute pools for the prompt-processing and token-generation phases), multi-GPU pipeline and tensor parallelism (splitting model layers and weight matrices across eight H100s), EAGLE-3 speculative decoding (a draft-model approach that predicts multiple tokens per forward pass), and a session-affinity header (x-session-affinity) that routes follow-up requests to the same node to raise prompt cache hit rates from 60% to 80%.

3× faster intertoken latency — 100 ms to 20–30 ms on Kimi K2.5
¶02 — Why it matters

The inference bottleneck is increasingly the constraint that determines which models are commercially viable in real products. A model that produces tokens at 100 ms per token feels noticeably sluggish in an interactive session; 20–30 ms is below the threshold most users perceive as a delay. Closing that gap without changing the model or the hardware is a pure systems win, and it compounds: lower latency means higher throughput per GPU, which reduces cost per token, which expands the set of use cases that pencil out economically.

The architectural choices Cloudflare describes — disaggregated prefill/decode, speculative decoding, session affinity for cache reuse — are not proprietary discoveries. What is notable is packaging all four into a single purpose-built engine in Rust, rather than patching vLLM or TensorRT-LLM incrementally. This signals that Cloudflare sees inference infrastructure as a strategic differentiator for Workers AI, not a commodity layer it can outsource to open-source maintainers.

For teams evaluating where to host inference workloads, the cold-start figure matters as much as steady-state throughput: large models loading in under 20 seconds means Workers AI can keep more model variants warmed without the sprawling always-on GPU reservations required by traditional deployments.

"We built Infire because existing inference engines weren't designed for the operational constraints of a globally distributed edge network." — Cloudflare engineering blog, April 16 2026
¶03 — What to watch

What to watch

  • Check whether Cloudflare publishes Infire as open source — if they do, it becomes an immediate reference implementation for edge-optimised inference that competing CDN/cloud players will need to match.
  • Evaluate the x-session-affinity header in your Workers AI integrations now: raising cache hit rate from 60% to 80% reduces prompt-processing cost on long-context sessions, which is a free latency and cost win for existing customers.
  • Watch Cloudflare's model roster over the next 90 days: Infire's <20-second cold start enables serving a wider catalogue of frontier models on-demand. If they onboard models beyond Kimi K2.5, it signals that inference-as-infrastructure is becoming a primary competitive surface, not a developer feature.
