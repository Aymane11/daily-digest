Zaya-1 API: call a voice-native medical AI model without a transcription pipeline

Zyphra's Zaya-1 accepts raw audio input and returns clinical-context-aware responses directly — no Whisper or equivalent transcription step. The 2.7B-parameter model runs on-device or via API, covers 14 languages, and is available under a research license with a free API tier.

Why it's worth trying: Every existing voice-enabled medical AI product chains together a speech-to-text model, a large language model, and a text-to-speech model. Each hop adds latency, cost, and a new failure surface. Zaya-1 collapses the first two hops into one end-to-end model, which means it also preserves prosodic cues — tone, hesitation, pace — that get lost in transcription and may carry clinical meaning. The key question to answer in testing is whether that end-to-end approach actually outperforms a well-tuned transcription + LLM pipeline on the tasks you care about.

Access and pricing: Research license — free API tier available with rate limits (details on the Zyphra developer portal). Commercial licensing requires contacting Zyphra directly. No HIPAA Business Associate Agreement is currently listed; do not use with real patient data until you confirm compliance documentation.

Quick start — under 10 minutes

Sign up at zyphra.com/developers, grab an API key, and send a short WAV file of a synthetic patient intake question. Compare Zaya-1's response with the output you'd get from Whisper + GPT-4o on the same audio — latency and clinical accuracy are the two numbers to capture.

Step-by-step
  1. Go to zyphra.com/developers, create an account, and copy your API key from the dashboard.
  2. Record or download a synthetic audio clip (30–60 seconds) of a patient describing a symptom — use a text-to-speech tool if you don't have a real recording. Keep it synthetic; never use real patient audio for testing.
  3. Install the Zyphra Python SDK: pip install zyphra-sdk
  4. Send the audio:
    from zyphra import ZyphraClient
client = ZyphraClient(api_key="YOUR_KEY")
with open("patient_intake.wav", "rb") as f:
    response = client.zaya.transcribe_and_respond(
        audio=f,
        context="clinical_intake",
        language="en"
    )
print(response.text)
print(f"Latency: {response.latency_ms}ms")
  5. Run the same audio through Whisper + your preferred LLM. Record wall-clock latency for both paths.
  6. Compare outputs on accuracy (did it catch the key symptoms?), latency, and any prosodic cues mentioned in Zaya-1's response that the transcription path missed.

What to observe

  • Does Zaya-1's response reference information conveyed by tone or pace (e.g., "the patient hesitated when describing pain onset") that a pure transcription would strip out?
  • Is end-to-end latency lower than your current transcription + LLM pipeline? The claim is a meaningful gap — verify it on your target device or API region.
  • Does the model correctly refuse or flag out-of-scope clinical questions (e.g., prescribing advice) that it should not answer autonomously?
