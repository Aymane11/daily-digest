Tilde: a browser-native AI terminal that gives you a real shell in seconds

Tilde (tilde.run) launches a sandboxed Linux shell in your browser with an AI layer that translates natural-language instructions into shell commands, explains output, and catches common errors before you run them. No install, no SSH config — open the URL and you have a working terminal.

Why it's worth trying: The problem Tilde solves is the friction between "I want to run a one-off command" and actually having a safe environment to do it. It targets developers who need a scratch shell for quick experiments, students learning the command line, and teams onboarding new engineers who don't yet have local environments set up. The AI layer is additive — you can type raw shell commands or describe what you want in plain English, and Tilde generates the command, shows a diff of what it will change, and waits for confirmation before executing anything destructive.

Access and pricing: Tilde offers a free tier with limited session length (30 minutes per session, one concurrent session). The paid tier ($12/month) removes session limits and adds persistent file storage across sessions. There is no self-hosted option at launch.

Quick start — under 5 minutes, zero setup

Open tilde.run in any browser. You land in a live shell immediately — no account required for the first session. Type a natural-language instruction to confirm the AI layer is working, then try a raw shell command to verify you have real execution.

Step-by-step
  1. Navigate to tilde.run — no sign-in required for a 30-minute guest session.
  2. In the prompt bar, type: list all files in the current directory sorted by size — Tilde generates ls -lhS and shows it before running.
  3. Press Enter to confirm. Observe actual shell output in the terminal panel below.
  4. Now try a raw command: curl -s https://httpbin.org/get | head -20 — this confirms you have real outbound network access.
  5. Test the safety layer: type delete everything in this folder — Tilde should surface a warning and require explicit confirmation before running any rm command.
  6. Sign up for a free account to persist your session and return to it within 24 hours.

What to observe

  • Does the AI-generated command match what you described, or does it make assumptions you didn't intend? Note any divergence — this is the key quality signal.
  • Does the destructive-action warning fire correctly on the delete prompt, and does it clearly show what would be deleted before asking for confirmation?
  • Measure time from URL open to first command executed — if it exceeds 10 seconds, the session provisioning overhead is a practical limitation for quick-scratch use cases.
