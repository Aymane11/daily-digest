ENGINEERING ON-DEVICE AI

I indexed a year of personal video locally with Gemma4-31B on a 2021 MacBook Pro (438 pts on HN)

A developer built a fully private semantic video search system using Gemma4-31B on Apple Silicon — no cloud, no API keys, 847 hours of footage indexed in 14 hours overnight.

BY · EDITORIAL TEAM · 2 MIN READ

★ WHAT HAPPENED

HN user kfogel published a write-up and open-source repository demonstrating full local video indexing with Gemma4-31B running via llama.cpp on a 2021 MacBook Pro M1 Pro (32 GB unified memory). The system samples one frame every 10 seconds, runs Gemma4-31B vision inference on each frame to generate a structured caption, embeds captions with nomic-embed-text, and stores them in a local SQLite-VSS index. Query latency for semantic search across 847 hours is under 200ms. Total processing cost: 14 hours, zero API fees, 100% on-device.

¶ 01 WHY · IT · MATTERS

This post is a benchmark disguised as a project write-up: it establishes that a 31B multimodal model can run at practical throughput on 2021 consumer hardware, which puts a boundary on the “you need a datacenter for this” argument. It also demonstrates the full local-first AI stack — inference, embedding, and vector search — using only open-source components. The privacy implication is significant: personal media indexing is one of the few AI use cases where users have a strong reason to avoid cloud APIs, and this shows it’s now feasible.

¶ 02 WHAT · TO · WATCH

The HN comments (312 at time of writing) surface two immediate replications: one on an M4 Max (same 847-hour corpus, 4.5 hours) and one on a 64 GB Threadripper workstation. Replication speed suggests the pattern will generalise quickly. Watch for Gemma4-31B quantisation updates that could reduce the 32 GB unified memory requirement to 16 GB — that would open the technique to the much larger installed base of 16 GB MacBook Pros.
