DEV TOOLS OPEN SOURCE

Ghostty leaves GitHub after 18 years of near-daily outages blocking serious development work

WED 29 APR 2026 · 3 MIN READ

TL;DR

Mitchell Hashimoto—GitHub user #1299, joined February 2008—announced on April 28 that his terminal emulator Ghostty will leave GitHub over chronic reliability failures. He describes marking his journal almost every day when outages block work. No new host is confirmed yet; a read-only mirror stays at the current GitHub URL.

¶01 · WHAT HAPPENED

Hashimoto posted on April 28 that GitHub "is no longer a place for serious work." He logs outages in a daily journal; almost every entry carries a mark for GitHub being unavailable. The triggering event was a large outage on April 27, but his reasoning is cumulative: GitHub Actions disruptions, web UI failures, and API instability have compounded to the point where he cannot rely on the platform.

He describes the decision as "super sad"—he is GitHub user #1299 and has visited the site almost every day for 18 years. Vagrant, his breakthrough open-source project, was partly created to impress GitHub. His other personal projects stay on GitHub for now; only Ghostty moves. Discussions with "multiple providers (both commercial and FOSS)" are ongoing. A read-only GitHub mirror will remain at the current URL.

¶02 · WHY IT MATTERS

Hashimoto is not a casual user making a protest move. He is the creator of Vagrant, Packer, Terraform, and Vault—tools that shaped how millions of engineers build infrastructure. His testimony that GitHub outages block him "almost every day" carries weight precisely because he has the engineering context to distinguish genuine platform degradation from user error.

The announcement collected 2,517 points on HN and 734 comments in 24 hours, suggesting the experience is broadly shared. GitHub's reliability problems have been reported episodically for years; this is the highest-profile departure to date and frames platform reliability as a first-order concern for open-source maintainers, not an inconvenience.

¶03 · WHAT TO WATCH

Check your own GitHub dependency. If GitHub Actions is in your critical path, evaluate whether you have a fallback. Run a postmortem: how many times in the last 90 days did a GitHub outage cost you measurable time? Quantifying this is the first step to deciding whether mitigation is worth the cost.

Watch where Ghostty lands. The destination will signal which alternative host has the features (Actions-equivalent CI, issue tracking, PR workflow) mature enough to attract high-profile migrations. Codeberg, GitLab, and self-hosted Forgejo are the most cited candidates in the HN thread.
