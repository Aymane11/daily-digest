AI AGENTS BUG

Claude Code regression: malware scan appended to every file read causes subagents to refuse all code output

A tracked regression in Claude Managed Agents (GitHub issue #49363, 213 HN points, 109 comments) describes a system prompt that appends a malware-scanning directive to every file read operation. The agent spends tokens and billing charges performing the analysis on each read, then incorrectly refuses to write any code—even after confirming no malware exists. Users are charged for each failed session. The bug is a false positive loop: the malware reminder context bleeds into the agent's safety evaluation for code writing, causing refusals that have nothing to do with the files read. The issue references a prior HN discussion that prompted Anthropic to address a similar problem. This class of regression—safety instrumentation producing downstream refusals via context pollution—is a known failure mode in long-context agent pipelines.

WHAT TO WATCH

Check your Managed Agents sessions for unexpected refusals after file read operations. If you see "I cannot write code that could be harmful" following clean file reads, you may be hitting this regression. Watch Anthropic's issue tracker for a fix; in the meantime, structuring prompts to explicitly separate the read context from the write task may reduce the false-positive rate. Track your per-session billing for unexpected spikes from repeated failed attempts.

FAILURE PATTERN

  1. Agent reads file
  2. Malware scan injected into context
  3. Scan confirms: no malware
  4. Agent refuses to write code anyway
  5. Session billed; user gets nothing

IMPACT

Billing charges for every failed session. Affects any Claude Managed Agents workflow that reads files before writing code.
