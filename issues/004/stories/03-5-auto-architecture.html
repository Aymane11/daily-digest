AI RESEARCH CPU DESIGN

Auto-Architecture: Karpathy's iterative improvement loop applied to CPU instruction set design

A project by Felipe Sens applies Karpathy's iterative development methodology—the "generate, evaluate, generate better" loop from nanoGPT and similar projects—to CPU architecture design rather than neural network design. The system runs automated tournaments where candidate CPU architectures compete on benchmark performance, and the winning characteristics seed the next generation of candidates. The project is documented as a GitHub-hosted blog post and has generated 144 HN points and 29 comments. It is an early exploration rather than a production tool, but it demonstrates the same AI-in-the-loop design iteration pattern that has been productive in software and beginning to appear in hardware. The approach side-steps the need for domain-specific human intuition in the early search phase by letting benchmarks serve as the fitness function.

WHAT TO WATCH

Watch for this pattern in your own design workflows. The Karpathy loop—fix an objective function, generate candidates, evaluate, iterate—is applicable anywhere you have a measurable fitness signal and a generative model. If you work in compiler optimization, database query planning, or API design, ask where your existing benchmarks could serve as a tournament judge for AI-generated candidates.

THE LOOP

  1. Define benchmark as fitness function
  2. Generate candidate architectures
  3. Run tournament evaluation
  4. Select winners
  5. Seed next generation
  6. Repeat
