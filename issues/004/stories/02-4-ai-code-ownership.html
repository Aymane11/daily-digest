LEGAL IP

Who owns the code Claude wrote? Three legal doctrines that determine the answer—and why none of them are settled

WED 29 APR 2026 · 3 MIN READ

TL;DR

A legal analysis published on HN (396 points, 374 comments) establishes three determinants of AI-generated code ownership: human authorship requirement (the DC Circuit's Thaler ruling makes predominantly AI-generated code uncopyrightable), work-for-hire doctrine (employers typically own code created using company tools), and GPL license contamination (models trained on copyleft code may reproduce obligations unknowingly). None is fully resolved in court.

¶01 · WHAT HAPPENED

Legal analyst Sena Evren published "Who owns the code Claude wrote?" on Substack, triggering the highest-engagement legal discussion about AI-generated code seen on HN this year. The piece synthesises three open legal questions into a decision framework developers can apply today.

The article's context is the March 2026 Anthropic leak: 512,000 lines of Claude Code's source code were accidentally published. Before breakfast on the day of the leak, a developer had used an AI tool to rewrite the entire codebase in Python. The repository hit 100,000 GitHub stars in a single day. Anthropic's DMCA campaign could target direct copies but not AI rewrites—because if Claude Code was substantially written by Claude itself, its copyright status is ambiguous.

This is not hypothetical. Anthropic's own lead engineer acknowledged that Claude Code was predominantly written by Claude. The US Copyright Office confirmed in January 2025 that works lacking meaningful human authorship are uncopyrightable. The question of whether Anthropic can enforce copyright on code Claude largely wrote is now a live issue.

¶02 · WHY IT MATTERS

Human authorship: Copyright requires "meaningful human creative decisions." Specifying objectives to an AI does not qualify; directing architecture and structure may. The DC Circuit's Thaler decision is the current standard. If you cannot articulate the architectural choices you made beyond the AI's output, your copyright claim is weak.

Work-for-hire: Employment IP clauses covering "work product created using company resources" or "company-licensed tools" typically assign AI-generated code to the employer, not the developer. Side projects built on company-licensed AI subscriptions may be subject to this clause.

GPL contamination: If a model was trained on GPL-licensed code and reproduces substantial verbatim portions, the GPL's copyleft obligations may apply to the output—even if the developer never knew the source. Running a license scanner on AI-generated code is no longer optional for commercial products.

¶03 · WHAT TO WATCH

Document your architectural decisions in commits. The difference between a defensible copyright claim and an unprotected work is evidence of human creative choices. "Accept AI suggestion" is not evidence. "Restructured the auth module to use a capability-token model instead of the AI's proposed role-based approach" is.

Review your employment IP clause before shipping side projects. If your employer provides your AI subscription, the "company resources" clause may apply. Confirm in writing before commercializing anything built with employer-licensed tools.

Run a license scan before launching. Tools like FOSSA, Snyk, and licensee can flag potential GPL contamination in your output. On Anthropic's commercial terms, you have some indemnification coverage; on consumer terms, you do not.
