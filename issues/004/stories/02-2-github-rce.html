SECURITY CVE

GitHub RCE via single git push: CVE-2026-3854 patched on GitHub.com, but 88% of Enterprise Server instances still vulnerable

WED 29 APR 2026 · 3 MIN READ

TL;DR

Wiz Research publicly disclosed CVE-2026-3854 on April 28—a CVSS 8.7 flaw in GitHub's git push pipeline that lets any authenticated user execute arbitrary code on backend servers with a single command. GitHub.com was patched in six hours on March 4. GitHub Enterprise Server admins must upgrade to 3.19.3, 3.18.6, 3.17.12, 3.16.15, 3.15.19, or 3.14.24. At disclosure, 88% of GHES instances remained unpatched.

¶01 · WHAT HAPPENED

Wiz Research discovered the vulnerability on March 4, 2026 and reported it to GitHub the same day. GitHub patched GitHub.com within six hours, then spent the following week preparing and releasing Enterprise Server patches before assigning the CVE on March 10. Public disclosure came April 28—50 days after the fix—giving GHES administrators time to apply patches.

The flaw is an injection vulnerability in the X-Stat header, an internal protocol component in GitHub's git push pipeline. By injecting semicolon-delimited fields through git push options, an attacker could: bypass sandbox protections, redirect hook directories, and execute arbitrary code as the git service user. On GitHub.com, the exploit granted "read access to millions of public and private repositories" on shared infrastructure nodes.

¶02 · WHY IT MATTERS

The attack requires only an authenticated GitHub account and a single git push. There is no complex payload or multi-step exploitation chain. On shared GHES infrastructure, successful exploitation means access to repositories belonging to other tenants on the same node—a supply chain risk for every organization hosting private code on unpatched instances.

The 88% unpatched rate at disclosure reflects the friction of enterprise upgrade cycles, not a lack of severity. GHES administrators often operate on quarterly patch windows; a 50-day embargo is shorter than many organizations' testing cycles for infrastructure upgrades.

¶03 · WHAT TO WATCH

If you run GHES: check your version now. Navigate to your admin console and confirm you are on 3.19.3, 3.18.6, 3.17.12, 3.16.15, 3.15.19, or 3.14.24. If not, treat this as a P0 upgrade. The exploit requires only authentication, not admin privileges.

Review your git push hooks and audit logs. Check CloudTrail/audit logs for anomalous X-Stat header values or unexpected process spawning from the git service user between March 1 and today. Even on patched GitHub.com, the window before the March 4 fix existed.

Watch for exploit publication. Now that the technical details are public, working proof-of-concept code is likely to appear within days. The window for unpatched GHES operators is closing.
