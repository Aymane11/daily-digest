Bugs Rust won't catch: 44 CVEs in Rust-rewritten coreutils reveal what memory safety leaves unguarded

An audit of 44 CVEs in uutils (a Rust reimplementation of GNU coreutils) identifies the bug classes that escape Rust's safety guarantees entirely. The largest cluster is TOCTOU (time-of-check-time-of-use) vulnerabilities: operations spread across multiple syscalls leave windows where symlinks can redirect paths. Permission race conditions arise when directories are created with default permissions then fixed afterward—the fix is to set permissions at creation time. Path comparison failures occur when string equality is used instead of fs::canonicalize(). UTF-8 assumptions silently corrupt binary data in tools like comm. Unhandled unwrap() panics crash processes on unexpected input. Zero buffer overflows, use-after-free bugs, or data races were found—exactly the class Rust prevents. The remaining vulnerabilities live at system boundaries, not within language semantics.

WHAT TO WATCH

Audit your Rust code for TOCTOU patterns. Search for any sequence where you check a path (metadata, exists, is_dir) and then act on it in a separate call. Replace these with atomic operations where possible. For path comparison, replace string equality with fs::canonicalize() on both sides. Replace unwrap() on user-facing input boundaries with proper error propagation.
