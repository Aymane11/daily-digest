NVIDIA Ising

Open-source AI models that accelerate quantum processor calibration and error correction

A vision-language model for calibration plus two 3D-CNN error decoders. 2.5× faster and 3× more accurate than pyMatching. Apache 2.0. Available on GitHub, Hugging Face, and build.nvidia.com.

TUE 28 APR 2026 · BY EDITORIAL TEAM

★ WHAT IT IS

NVIDIA Ising is a family of three open-source AI models that address the two primary operational bottlenecks in running quantum processors: calibration and error correction. The calibration model is a vision-language model that interprets quantum processor measurement outputs and drives automated tuning, reducing what currently takes days of manual work to hours of automated operation. The error correction suite offers two 3D convolutional neural network variants: one optimized for maximum accuracy and one for real-time speed. Both outperform pyMatching—the current industry standard error decoder—by 2.5× on speed and 3× on accuracy. All models are Apache 2.0 licensed and available on GitHub, Hugging Face as pretrained weights, and as NIM microservices on build.nvidia.com for cloud deployment without local GPU setup.

¶ 01 WHY · IT · MATTERS

Calibration and error correction are not research curiosities—they are recurring operational costs that every quantum computing lab pays continuously. A quantum processor cannot run experiments while it is being recalibrated; reducing that window from days to hours directly increases the number of useful experiment cycles per week. Error correction is even more fundamental: the rate of undetected errors is the primary variable that determines whether a quantum circuit can run long enough to produce a result that matters. A 3× improvement in error correction accuracy means substantially longer coherent circuits are feasible on existing hardware, without requiring better physical qubits. NVIDIA open-sourcing both models rather than keeping them proprietary accelerates the entire ecosystem and signals that AI-assisted quantum operations is a domain they intend to dominate by seeding the community.

¶ 02 HOW · TO · TRY · IT ~20 MIN
01

Clone the repository: git clone https://github.com/NVIDIA/Ising. Review the README for hardware requirements—the 3D-CNN inference runs on CPU for evaluation but benefits significantly from a GPU.

02

Install dependencies: pip install -r requirements.txt. Download pretrained weights from Hugging Face: huggingface-cli download nvidia/ising-decoder.

03

Run the benchmark against pyMatching on a publicly available quantum circuit dataset (the repo includes sample syndrome data). Record accuracy and latency for both Ising variants and pyMatching baseline.

04

Alternatively, use the NIM microservice on build.nvidia.com for zero-install cloud inference: create an account, navigate to the Ising NIM, and submit a syndrome string via the REST API to get a decoded error correction output.

¶ 03 WHAT · TO · OBSERVE

Verify the 3× accuracy claim independently on the sample syndrome data before drawing conclusions—benchmark numbers from vendors deserve independent replication. Note whether the accuracy advantage is consistent across different error rates (low, medium, high physical qubit error rates), since real quantum processors operate across this spectrum depending on hardware quality. Watch for adoption signals from the major hardware vendors: if IBM Quantum, Google Quantum AI, or IonQ incorporate Ising into their calibration or error correction pipelines, the 2.5× speed claim becomes production-validated at scale. Also check whether the NIM API latency (network + inference) actually outperforms a local pyMatching call—for real-time error correction in a quantum control loop, end-to-end latency is what matters, not just model inference speed.
