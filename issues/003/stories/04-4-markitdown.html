MarkItDown

Microsoft’s open-source document-to-Markdown converter for LLM pipelines

One command converts PDF, DOCX, XLSX, PPTX, HTML, images, audio, and ZIP archives to clean Markdown. MIT license. Python 3.10+. v0.1.5 released Feb 20, 2026.

TUE 28 APR 2026 · BY EDITORIAL TEAM

★ WHAT IT IS

MarkItDown is a Python utility from Microsoft that converts virtually any document format to clean Markdown text—the format that LLMs consume most efficiently. It handles PDF (with OCR fallback), Word DOCX, Excel XLSX (tables become Markdown tables), PowerPoint PPTX, HTML, images (via optional vision model integration), audio files (via transcription), and ZIP archives (recursively processes contained files). The output prioritizes semantic structure—headings, lists, tables, code blocks—rather than pixel-perfect layout fidelity. v0.1.5, released February 20, 2026, added improved table extraction from PDFs and better handling of multi-column layouts. It runs as a CLI tool or as a Python library you can embed in preprocessing pipelines. MIT license, no vendor lock-in, no API calls required for the core conversion pipeline.

¶ 01 WHY · IT · MATTERS

The practical bottleneck in most enterprise RAG and document-processing pipelines is not the LLM—it is getting structured, clean text out of the diverse document formats that actually exist in organizations: scanned PDFs, financial spreadsheets, PowerPoint decks, email attachments. MarkItDown is a single-dependency solution to that preprocessing problem, and Microsoft’s decision to open-source it under MIT means it can be embedded in any commercial pipeline without licensing friction. The table extraction improvement in v0.1.5 is particularly significant: financial and legal documents that contain tables are among the highest-value enterprise document types, and table extraction from PDFs has historically been the hardest conversion problem. A tool that reliably gets tables out of PDFs as Markdown tables dramatically reduces the custom preprocessing engineering that teams currently build and maintain.

¶ 02 HOW · TO · TRY · IT ~5 MIN
01

Install: pip install markitdown. Requires Python 3.10+. For optional OCR support on scanned PDFs add: pip install markitdown[ocr].

02

Convert a document: markitdown input.pdf > output.md. Works identically for DOCX, XLSX, PPTX, and HTML inputs. No flags needed for basic conversion.

03

Test a document that contains tables: a financial report PDF or an XLSX file with multi-column data. Check whether the tables come out as valid Markdown tables that an LLM can reason over without additional parsing.

04

Use in Python: from markitdown import MarkItDown; md = MarkItDown(); result = md.convert("file.pdf"); print(result.text_content). Drop this into your RAG preprocessing pipeline in place of whatever custom extraction code you currently run.

¶ 03 WHAT · TO · OBSERVE

Test conversion quality on the document types that are hardest in your specific pipeline: scanned PDFs with irregular column layouts, spreadsheets with merged cells, PowerPoints with text in shapes rather than text boxes. Compare the token count of the MarkItDown Markdown output to a naive text extraction (e.g., pdfplumber plain text) on the same documents—Markdown structure typically reduces the tokens needed by an LLM to correctly parse tables and headings. Also measure end-to-end answer quality in your RAG system: if the downstream LLM answers are more accurate on table-heavy queries after switching to MarkItDown, that is the real signal. Watch whether Microsoft integrates MarkItDown into Azure AI Document Intelligence as a managed service, which would add SLA and support guarantees for enterprise adoption.
