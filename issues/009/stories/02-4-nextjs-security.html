SECURITY WEB NEXT.JS

Next.js ships critical security release fixing 13 CVEs

Patches for auth bypass, DoS (CVE-2026-23870), SSRF via WebSocket, cache poisoning, and XSS — update to 15.5.18 or 16.2.6 immediately

BY · EDITORIAL TEAM · 3 MIN · SECURITY · WEB

Vercel published a coordinated security release for Next.js on May 7 covering 13 advisories. Critical vulnerabilities include an authentication bypass via segment-prefetch, a denial-of-service in React Server Components (CVE-2026-23870), SSRF via WebSocket upgrades, cache poisoning, and cross-site scripting. All users should update to Next.js 15.5.18 or 16.2.6.

05 WHAT IT MEANS
3 TAKEAWAYS · LINKS
01

Update immediately — this affects production deployments

The auth bypass vulnerability is the most critical. Pages protected by middleware (the recommended Next.js auth pattern) may be accessible without authentication. Run `npm update next` and redeploy. Test auth-required routes after updating.

02

RSC attack surface is expanding

CVE-2026-23870 targets React Server Components — a relatively new attack surface. Teams using RSC should review their data fetching patterns and ensure sensitive operations happen in server actions, not during rendering.

03

Audit WebSocket usage in your app

The SSRF vulnerability via WebSocket upgrades is subtle. If your app uses WebSockets, review upgrade request handling. Consider rate-limiting WebSocket connections and validating upgrade URLs.
