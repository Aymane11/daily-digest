Agent Skills: a framework for making AI coding agents follow senior engineering discipline

Addy Osmani releases a 20-skill, six-phase workflow system for AI coding agents. The core insight: agents execute workflows, not essays. Skills encode checkpoints and exit criteria that make steps like spec, test, and review impossible to skip.

AI ENGINEERING DEVELOPER TOOLS OPEN SOURCE
TL;DR

Addy Osmani (Chrome team, Google) published a post and MIT-licensed GitHub repository with 20 "skills" — markdown workflow files injected into agent context — covering six software lifecycle phases: Define, Plan, Build, Verify, Review, Ship. The project has 26K GitHub stars. The key design principle: skills encode checkpoint-based workflows with anti-rationalization tables (pre-written rebuttals to the excuses agents give for skipping steps). No step is advisory; all terminate with concrete evidence (test runs, logs, approvals).

¶01 WHAT HAPPENED

Addy Osmani published "Agent Skills" — a system for encoding senior engineering practice into AI coding agents through reusable workflow markdown files. The post describes five load-bearing design principles: process over prose, anti-rationalization tables, verification as non-negotiable, progressive disclosure (activate only relevant skills per phase to preserve context tokens), and scope discipline ("touch only what you're asked to touch").

The six phases are: Define (write a spec before touching code), Plan (decompose the spec into tasks), Build (implement within scope), Verify (tests pass, evidence collected), Review (code review approval), Ship (deploy with confirmed rollback path). Each phase has exit criteria — conditions that must be true before the agent proceeds. Agents cannot exit a phase by claiming "it looks fine."

The anti-rationalization tables are the most novel element: they pre-enumerate the excuses agents give for skipping steps ("we'll add tests later," "this is too small to need a spec") alongside the documented reasons those excuses produce worse outcomes. This is the agent equivalent of pre-mortem planning applied to engineering discipline.

¶02 WHY IT MATTERS

AI agents default to the shortest path to a passing output — which means skipping specs, writing minimal tests, and treating review as optional. These are exactly the shortcuts that accumulate as technical and cognitive debt. Skills make discipline structural rather than advisory: the agent cannot call a phase complete without satisfying its checklist.

The framework is also applicable to human team processes: the same checkpoint-based workflow files can be imported into onboarding docs, PR templates, or team runbooks. The MIT license means teams can adapt them freely.

¶03 WHAT TO WATCH
  • Clone the repository and run /spec on your next feature before writing any code. The Define phase forces you to write the acceptance criteria first — try it on one story this sprint and measure whether the implementation scope stays tighter than usual.
  • Evaluate the anti-rationalization tables for your team's specific failure patterns — the most useful ones will be the excuses your team actually uses, not the generic ones. Customize them.
  • Watch whether Cursor, Claude Code, or Gemini Code Assist builds native skill injection into their agent interfaces — the 26K stars signal demand for this pattern at the IDE layer.
