OpenAI Realtime API

Real-time speech-to-speech AI with 250–500 ms end-to-end latency. The new gpt-realtime-mini snapshot adds +18.6 pp instruction-following and +12.9 pp tool-calling accuracy. Handles streaming audio in/out, interruptions, and function calling mid-speech.

VOICE AI WEBRTC OPENAI

WHY TRY THIS

The Realtime API is the only production-grade speech-to-speech API that handles interruptions naturally — when a user talks over the model, it stops gracefully instead of finishing its sentence. The new mini snapshot makes it practical for cost-sensitive deployments: tool-calling accuracy is now reliable enough to build phone bots and voice agents that actually complete tasks.

Problem it solves: building voice interfaces that feel like real conversation, not a voice-over-IVR. The latency target (250–500 ms) keeps the back-and-forth from feeling robotic.

ACCESS & PRICING

  • Paid API — requires an OpenAI API key with billing enabled
  • gpt-realtime-mini — lower cost than the full Realtime model; exact pricing at platform.openai.com/pricing
  • Free alternative: Whisper (speech-to-text) + any LLM + TTS gives a similar pipeline but with higher latency and no interruption handling
  • WebRTC and WebSocket transports both supported

HANDS-ON · TRY IT

Prerequisites: OpenAI API key, Node.js 18+

STEP 1 — Install the SDK

npm install openai

STEP 2 — Create a WebSocket session

import OpenAI from "openai";

const client = new OpenAI();

const session = await client.beta.realtime.sessions.create({
  model: "gpt-4o-realtime-preview-2026-04-30",
  voice: "alloy",
});

console.log("Session token:", session.client_secret.value);

STEP 3 — Connect and stream audio

# Full WebRTC/WebSocket example:
# platform.openai.com/docs/guides/realtime

STEP 4 — Add a tool call

// In session config:
tools: [{
  type: "function",
  name: "get_weather",
  description: "Get current weather for a city",
  parameters: {
    type: "object",
    properties: {
      city: { type: "string" }
    },
    required: ["city"]
  }
}]

WHAT TO OBSERVE

  • Speak a question and measure the time until the first audio byte arrives — should be under 500 ms on a good connection
  • Try interrupting mid-response: the model should stop within ~200 ms of you starting to speak
  • Invoke a tool call mid-conversation ("what's the weather in Paris?") and verify the function fires correctly before the model continues speaking
  • Compare latency between WebSocket and WebRTC transports for your region
