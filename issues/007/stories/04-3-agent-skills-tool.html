Agent Skills

20 markdown workflow files for AI coding agents covering the full software lifecycle — Define, Plan, Build, Verify, Review, Ship. Makes spec writing, testing, and code review impossible to skip. 26K GitHub stars. MIT licensed.

OPEN SOURCE AI AGENTS DEVELOPER WORKFLOW

WHY TRY THIS

AI coding agents default to the shortest path to a passing output — which means skipping specs, writing minimal tests, and treating review as optional. Agent Skills encodes senior engineering discipline as checkpoint-based workflows that the agent cannot bypass. Each phase has exit criteria; each shortcut has a pre-written rebuttal in the anti-rationalization tables.

Problem it solves: the quality gap between "AI can write code" and "AI writes code with the same discipline as a senior engineer." Works with Claude Code, Cursor, Gemini Code Assist, and any agent that accepts markdown context files.

ACCESS & PRICING

  • Completely free — MIT licensed, no account required
  • Works with any AI coding agent that accepts context injection (Claude Code, Cursor, Gemini, Copilot Workspace)
  • No external API calls — pure markdown files you copy into your repo or agent config

HANDS-ON · TRY IT

Prerequisites: any AI coding agent (Claude Code, Cursor, etc.), git

STEP 1 — Clone the repository

git clone https://github.com/addyosmani/agent-skills
cd agent-skills

STEP 2 — Run /spec on your next feature

# In Claude Code or your agent:
/spec "Add user authentication with OAuth2"

# The /spec skill forces the agent to produce:
# - Problem statement
# - Acceptance criteria (numbered)
# - Out of scope (explicit)
# - Success metrics
# Before writing a single line of code

STEP 3 — Run /plan after spec is approved

/plan
# Agent decomposes the spec into:
# - Ordered task list
# - Dependencies between tasks
# - Estimated complexity per task
# Cannot proceed to /build without explicit approval

STEP 4 — Build and verify

/build   # Implements within approved scope only
/test    # Must produce passing test output as evidence
/review  # Checklist: scope, tests, perf, security
/ship    # Only after review approval + rollback plan

WHAT TO OBSERVE

  • Run /spec on a real feature and compare the resulting acceptance criteria to what you would have written without it — look for gaps you would have missed
  • Run /build without /spec first and observe whether the agent tries to skip directly to code — that's the default behavior the skills are designed to prevent
  • After /verify, check if the agent produces actual test output (stdout, pass count) rather than just claiming tests pass — evidence of completion vs. assertion of completion
  • Count the lines of code in the first /build output — it should stay close to 100 lines per PR by the scope discipline rule

THE 6 PHASES

/spec — Define: write before touching code

/plan — Plan: decompose + dependencies

/build — Build: within scope only

/test — Verify: evidence required

/review — Review: checklist approval

/ship — Ship: rollback plan required
