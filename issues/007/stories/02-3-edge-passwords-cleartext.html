Microsoft Edge decrypts and holds all saved passwords in process memory at startup — Microsoft calls it by design

A responsible disclosure found that Edge is the only Chromium-based browser that loads every saved credential into memory whether or not you visit the associated site. Attackers with local access can dump all passwords from any non-elevated process. Microsoft declined to fix it.

TL;DR

Microsoft Edge decrypts every credential in your saved password manager and keeps them resident in process memory from the moment the browser launches — regardless of whether you visit those sites. Chrome does not do this. An attacker with any local access (remote admin, shared terminal server session, or co-located process) can read all passwords without elevation. Microsoft's official response: this behavior is "by design."

¶01 WHAT HAPPENED

Security researcher L1v1ng0ffTh3L4N published a responsible disclosure finding that Microsoft Edge decrypts every saved password in its built-in password manager at browser startup and holds them in process memory for the entire session. The passwords remain accessible in memory even when you are not on any site that uses those credentials — they are loaded preemptively.

This behavior differs from Chrome, which reads and decrypts credentials on demand — only when you visit a site that needs them. Edge's approach means a full credential dump is possible from any process running on the same machine, without requiring administrator privileges.

The risk is especially acute in shared environments: terminal servers, VDI sessions, or any machine where multiple users or processes run concurrently. Remote access tools with code execution capability (not just admin access) can extract all saved passwords in a single memory read. Microsoft was notified through responsible disclosure channels. Its response: the behavior is intentional and will not be changed.

¶02 WHY IT MATTERS

"By design" is the most damaging possible response here. It closes the fix pathway, it signals no timeline will ever change it, and it makes the risk permanent rather than temporary. Organizations that have deployed Edge as their enterprise browser standard — which is a large fraction of Microsoft 365 customers — now have documented confirmation that all employee credentials in the Edge password manager are fully accessible to any attacker who achieves code execution on an endpoint.

The practical mitigation is to not use Edge's built-in password manager. Use a dedicated password manager (Bitwarden, 1Password, etc.) that holds credentials in its own encrypted vault, releases them only when explicitly unlocked, and does not expose them to other processes running on the same machine.

¶03 WHAT TO WATCH
  • Audit your team's password manager usage today — if any team members use Edge's built-in password manager on shared or RDP-accessible machines, migrate them to a dedicated password manager before the week is out. This is a one-hour task per person.
  • Check your enterprise browser policy: if Edge is the default, issue guidance via IT policy doc or Slack to stop saving new passwords in Edge and migrate existing ones. Frame it as hygiene, not panic.
  • Watch whether Microsoft reverses its "by design" position after public pressure — the HN and security community response has been strong. A policy reversal would be the right outcome but is not guaranteed.
